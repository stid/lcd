# No Overengineering

The lightness rule — LCD applies it to its own process and to the code you write.

- Make only the changes the work requires or that are clearly necessary.
- Don't add features, options, or abstractions that weren't asked for.
- Don't add error handling for conditions that can't occur.
- Three similar lines beat a premature abstraction; extract only on the third real repetition.
- If something becomes unused, delete it.
- When in doubt about process weight, choose the lighter lane.
