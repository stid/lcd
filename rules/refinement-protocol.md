# Refinement Protocol

When asked to change, remove, or adjust something already implemented — and when LCD's autonomous
`refine` verb corrects a STEP/task/MAP entry mid-flight:

1. **Restate** the specific change as you understand it.
2. **Name what stays unchanged** — the elements you will NOT touch.
3. **Make the edit** only after 1–2.

A request to remove X never means removing the whole feature that contains X. When the change is
ambiguous, ask which specific element to change before editing. (LCD's `refine` may correct
*mechanical* drift autonomously, but escalates anything that implies a change of **intent**.)
